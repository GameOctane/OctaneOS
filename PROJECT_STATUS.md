## Why this exists
A $150 weekend build that anyone can make, own completely, and runs every retro game — open source from silicon to firmware.

## Strategic picture
OctaneOS is the foundation everything else in GameOctane sits on. It is no longer a bring-up project: it ships signed over-the-air updates (0.8.0+), RetroAchievements out of the box, per-player profiles with their own saves and logins, fan support, and working audio. Profiles are proposed upstream as batocera-emulationstation#2207 (open; the maintainers' comments have not been reviewed here yet). The next big unknown is the wireless dock and handheld (Part 2 of docs/ROADMAP.md); software work in Part 1 comes first.

## Ideas / Backlog
- **Chiaki — PS4/PS5 Remote Play** — Chiaki is an open-source Remote Play client for Linux with ARM support. Would let Octane stream PS4/PS5 games directly from a console on the local network. Touch screen on the Octane could map to PS4/PS5 touchpad input. Batocera has a chiaki package worth evaluating for aarch64 compatibility.
- **Steam Link** — Valve's official ARM Linux Steam Link client streams any Steam game from a PC on the local network. Batocera ships a steamlink package; needs evaluation for aarch64. Zero PC-side setup beyond enabling Remote Play in Steam.
- **Second-screen achievement companion** — pair OctaneOS over local WiFi with a running [Achievement Scavenger](https://github.com/batureren/achievement-scavenger) instance on the player's PC/console setup. Scavenger already knows what game just launched on Steam/PSN/Xbox and holds valid platform sessions; OctaneOS acts as a lightweight display client showing live missable-item warnings, hints, and progress while you play on another platform. RetroAchievements is already covered natively on-device — this extends the same idea to non-emulated platforms. Idea credit + concept borrowed with permission from Batu Ozdogan ([@batureren](https://github.com/batureren)), author of Achievement Scavenger. Needs: pairing/discovery protocol, a small local API on Scavenger's side (author receptive to adding one), and an OctaneOS-side display client.
- **Sane default volume (QOL)** — idea from the user (2026-11-05): ship with the master volume at about 50% so the first boot is not blaring. Not built; check where Batocera sets the first-boot volume (`audio.volume` in batocera.conf / the ES audio setting) and whether the A733 default is loud.
- **Show the profile's display name next to its folder (polish)** — a profile rename changes only the display name (stored as `display_name=` in the profile's conf); the folder under `/userdata/profiles/` keeps its original ID (`test`, and `.default` for main). That is deliberate (no save moves, safe with quotes and slashes, stable Syncthing paths), but someone browsing the network share sees the ID, not the friendly name. Options: a small readme/name file inside each profile folder, or naming the folder from the display name only when the profile is created. Raised by the user 2026-11-05 during board testing; not built.
- **Switch message shows the folder ID, not the display name (bug, small)** — on the PROFILES screen, choosing a renamed profile (e.g. `Dad's "games"`) says "SWITCHED TO PROFILE: test" because `GuiProfilesSettings.cpp` prints the folder name; the list itself uses the display name. One-line fix (patch 0007 draft); needs a rebuild to test. Found by the user on the board 2026-11-05.
- **N64 libretro core (`mupen64plus-next`) is too slow on the A733; standalone mupen64plus is fine** — found 2026-11-07 on the test board (user-reported: the lag was only in the libretro core, standalone ran fine). Zelda OoT lags even in the RetroArch menu with the libretro core. Sample while lagging: 38-40 C, 4.7 GB free, ES idle; the game's main thread sat on a little core (core 3, 1.8 GHz max) at about 68% while the two big cores idled at 408 MHz, so it is not CPU-pegged; internal resolution / GPU is the guess (not measured). Low priority because standalone is the default. Ideas: lower the core's default internal resolution, or hide the libretro N64 choice if it stays slow. Not investigated further.
- **Dreamcast performance needs work (user report)** — 2026-11-07: Sonic Adventure (Flycast, libretro core and the standalone) runs and saves correctly per profile, but the user says performance needs work. Not measured: no frame rate, no sample while it was slow, no core options or resolution checked. Next time: sample temperature, clocks and CPU while it is slow, and check the internal resolution setting. Also the shared `/userdata/bios/dc/dc_nvmem.bin` (language/region flash) is shared by every profile.


## Blockers
- GameCube/Wii games do not start (GPU driver; standalone Dolphin not in the image, libretro core stalls). Revisit when the open GPU driver matures.
- Some units switch off under heavy load with no heatsink (#11). Needs an answer before a case is sealed.
- Picture can stay black after a monitor is switched off and on.
- Wireless dock: glass-to-glass latency estimated 55-65 ms against a 33 ms target; not met yet.
