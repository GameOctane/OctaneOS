## Compatibility

- **Update over the air:** yes, from v0.7.0.
- **Back up first:** yes, as always (keep the device powered during the update).
- **Needs a fresh install:** no.
- **Tested on:** Radxa Cubie A7S. Fresh install (boots, plays, settings seeded); the one-time settings change on an existing card (four cases: first boot, a card from before the fix, a value you set yourself, a line you removed on purpose); DS audio and frame rate; a 10-minute thermal run with a fan; the signed-update check on the device (with test keys: an unsigned update, one signed by an unknown key, an edited manifest and an older version were all refused before anything was written, and a correctly signed update installed with every file matching the archive). The first signed release is installed on 0.7.0 devices by their old updater, which checks only the checksum (see above).

## What changed

**Signed updates.** Every update now carries a signature made with a key that is kept offline, and devices install nothing that does not verify. A signed update is also refused if it is for another board or older than what is installed. Devices still on 0.7.0 do not check signatures, so **this first signed update reaches them without that protection**; every update after it is checked. Details: [docs/update-signing.md](https://github.com/GameOctane/OctaneOS/blob/main/docs/update-signing.md).

**Nintendo DS: no more audio warble.** On a 120 Hz screen the DS emulator's vsync made a slightly late frame wait for the next 120 Hz slot, so the game hovered around 50 fps and the audio had gaps about 14% of the time. With vsync off it holds 58-61 fps and the gaps are gone (0.0-0.5%). We saw no tearing. Other systems are unchanged.

**Fan support.** The kernel now drives a fan on the board's fan header (J7) and speeds it up in four steps as the chip warms (55, 60, 66 and 72 C). This part is software only: the speed control on the header is **not tested on hardware yet**. A fan wired straight to 5 V and ground works regardless; with a small fan blowing on the heatsinks the chip stayed at 42 C (peak 45 C) in a 10-minute DS test, with no throttling, where it reached 80 C and throttled without one. Wiring, a printable bracket and the details: [docs/fan-cooling.md](https://github.com/GameOctane/OctaneOS/blob/main/docs/fan-cooling.md).

**Your own display is detected.** The board no longer forces one built-in 120 Hz display profile onto whatever is connected, so it reads your display's real modes. Tested on a 144 Hz monitor (60, 120, 144 and 165 Hz modes seen, 120 Hz in use, unplug and replug recovered in about 7 seconds).

**Smoother video.** The compositor no longer hands the screen straight to a game ("direct scan-out"), which removes the scan-out failures we saw.

**Settings changed on existing cards** (written once at the first boot after the update; a value you already set is never touched, and if you change or delete it afterwards it stays that way):
- Nintendo DS: `nds.retroarch.video_vsync=false`. To turn vsync back on, set `nds.retroarch.video_vsync=true` in `batocera.conf` (or in RetroArch's menu).

## Known issues

- **120 Hz displays.** The old forced display profile was a fixed 120 Hz profile. It is gone, so every display is now detected by its own modes. This is tested on one 144 Hz monitor (120 Hz mode in use) and **not on other 120 Hz displays**. If your display shows no picture or the wrong refresh rate after updating, please tell us which model.
- After the monitor is switched off and on, or goes to sleep, the picture may need a moment or a replug to come back. It recovered in our test, but we have only repeated it once.
- Some units can switch off completely under heavy load with no heatsink (cause not confirmed, heat is the main suspect). A heatsink and a fan avoid it in our tests.
- The speed control for a fan on the board's header is untested on hardware (see above).
- Standalone emulators (PPSSPP, Flycast, DuckStation, standalone mupen64plus) have their own vsync settings and were not tested for this change.

## Files

- `boot.tar.xz` (+ `.md5`, `.sha256`): the over-the-air update. Devices fetch this.
- `boot.tar.xz.manifest` and `boot.tar.xz.manifest.sig`: the signed description of that update (board, version, size, SHA-256). Devices with signature checking refuse an update that does not match.
- `OctaneOS-<version>.img.gz`: a full image for a fresh install.
- `SHA256SUMS`: check downloads with `sha256sum -c SHA256SUMS`.
