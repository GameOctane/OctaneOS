## Compatibility

- **Update over the air:** yes, from v0.8.1 (and v0.8.0).
- **Back up first:** yes, as always (keep the device powered during the update). This release also changes what happens the first time you switch profile (see below), so a copy of `/userdata/saves` is worth having.
- **Needs a fresh install:** no.
- **Tested on:** Radxa Cubie A7S. A test build of these changes was run on a real device: first profile switch, the profile name on screen, saves and savestates of two profiles staying apart. The update over the air from 0.8.1 to 0.8.2 itself was also run on a real device: the signature was accepted, the unit restarted into 0.8.2, and a game was started and played afterwards with picture and sound. Not yet run on a device: Amiga saves following the profile, and renaming the default profile.

## What changed

**Switching profile for the first time no longer deletes your old saves.** Before, the first switch copied `/userdata/saves` and `/userdata/states` into the hidden default profile and then removed the originals, even if a copy had failed. Now it copies first and checks, and only then *renames* the old folders to `saves.migrated` and `states.migrated`, so nothing is deleted. It runs once. After you have checked your games, you can delete the `.migrated` folders to get the space back.

**The active profile is shown on screen.** A small box at the top of the screen shows the profile's name while you play or browse. The main menu footer says "Profile: <name>", and a message appears at start-up. Alerts (music, updates) appear below the box. You can change it under **User interface settings > Show profile name** (automatic, always, never). It only appears when profiles are in use.

**Amiga saves follow the profile.** Amiga (Amiberry) saves used to go to a shared folder whatever the profile. They now go into the active profile's folder. The first time, your old Amiga saves are *copied* (never moved) into the default profile.

**Settings changed on existing cards:** none. Profiles you already made keep working.

## Known issues

- **GameCube and Wii games do not start.** The default emulator for both is a standalone Dolphin that is not part of this image, so a game fails at launch. The libretro Dolphin core is in the image, but on this GPU it stalls at start-up, so we have not made it the default. Cause is the GPU driver; tracked, no fix yet.
- **USB-C to DisplayPort with a plain (non power-delivery) cable** is tested only with a cable that does negotiate power delivery. If your screen stays black or says "no signal", please open the issue form "No picture, or the wrong picture, on a display".
- After the monitor is switched off and on, or goes to sleep, the picture may need a moment or a replug to come back.
- Some units can switch off completely under heavy load with no heatsink (heat is the main suspect). A heatsink and a fan avoid it in our tests.
- Some emulators keep saves outside the profile folders (parts of MAME, Saturn, Dreamcast, PS2 and others have not been checked yet). Saves from those are shared by all profiles for now.
- **A new profile starts with a copy of the RetroAchievements login of the profile that created it.** Two profiles can then show the same name in the profile list and on the badge. Rename the new profile in the profile screen, and enter its own RetroAchievements login. Fixed in the next release.
- Standalone emulators (PPSSPP, Flycast, DuckStation, standalone mupen64plus) have their own vsync settings and were not tested.

## Files

- `boot.tar.xz` (+ `.md5`, `.sha256`): the over-the-air update. Devices fetch this.
- `boot.tar.xz.manifest` and `boot.tar.xz.manifest.sig`: the signed description of that update (board, version, size, SHA-256). Devices with signature checking refuse an update that does not match.
- `OctaneOS-<build>.img.gz`: a full image for a fresh install.
- `SHA256SUMS`: check downloads with `sha256sum -c SHA256SUMS`.
