## Compatibility

- **Update over the air:** yes, from v0.6.9 (and earlier 0.6.x).
- **Back up first:** yes. The first update to 0.7.0 is installed by the updater you already have, which unpacks straight over the boot partition, so keep the device powered and back up your saves first (see UPGRADING.md).
- **Needs a fresh install:** no.
- **Tested on:** Radxa Cubie A7S. Updated from the published v0.6.9 with its own updater, with games, saves and Wi-Fi on the card (all kept); fresh install; download of an update from GitHub over HTTPS.

## What changed

**A safer updater.** From the update after this one, the updater refuses anything without a matching checksum, unpacks into a staging folder and checks it is for your board and complete before it touches the boot partition, always locks the boot partition again, downloads over HTTPS only and resumes after a dropped connection, and runs one update at a time.

**Safer network defaults.**
- The shared folder (`\\octaneos\share`) no longer shows guests the `system` folder (SSH keys, settings including the Wi-Fi password) or the RetroAchievements credential files. Saves, ROMs, BIOS and themes work as before.
- The NFS server only runs if you export something.
- Syncthing's web page is only reachable from the device itself. To open it to the network again, set `system.syncthing.lan=1` in `batocera.conf`. To reach it from your computer: `ssh -L 8384:127.0.0.1:8384 root@octaneos`.
- Fresh installs have Wi-Fi switched on (no network is joined until you add one, and the country is not preset: set yours).
- The default SSH login is still `root` / `linux`. A device password is planned for the next update: change it yourself meanwhile.

**Cooler and easier to diagnose.** The kernel now throttles the CPU at 80 °C (the previous release had no thermal protection), reports lockups, and keeps a bigger kernel log. Heavy games on a bare board still run hot: a heatsink and a little airflow help a lot (a small fan made about a 20 °C difference in our tests).

**Boot.** The intro plays once, not twice.

**Nintendo 64.** Hotkey + Start now exits N64 games. We also fixed a video flicker in the N64 emulator's graphics plugin (flat surfaces drawn on top of each other flashed). We found it by testing the flickering ground in Ocarina of Time, and the fix is a general video setting, so other games may benefit too; we have only tested Ocarina of Time. It is on by default for fresh installs. On an existing install, add these three lines under `[Video-Glide64mk2]` in `/userdata/system/configs/mupen64/mupen64plus.cfg` (or set the values if they exist):

    force_polygon_offset = True
    polygon_offset_factor = -1.000000
    polygon_offset_units = -1.000000

**For testers.** The flight recorder (`octane.flightlog=1`) and the boot-video trace (`octane.splashtrace=1`) are off by default and only switched on in `batocera.conf`.

## Known issues

- Some units can switch off completely under heavy load with no heatsink. The cause is not confirmed (heat is the main suspect). Please report it, with what you were running.
- On an existing install, Hotkey buttons only work if your controller's configuration includes the button codes; if Hotkey + Start does nothing on your pad, tell us which one.
- The update removes files you keep on the boot partition that are not part of the update (the old updater has no exceptions; the new one spares `boot-custom.sh` and `postshare.sh`).

## Files

- `boot.tar.xz` (+ `.md5`, `.sha256`): the over-the-air update. Devices fetch this.
- `OctaneOS-<build>.img.gz`: a full image for a fresh install.
- `SHA256SUMS`: check downloads with `sha256sum -c SHA256SUMS`.
