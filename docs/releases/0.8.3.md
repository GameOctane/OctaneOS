## Compatibility

- **Update over the air:** yes, from v0.8.2 (and v0.8.1). The signed update is run on a real device before this version is announced.
- **Back up first:** yes, as always (keep the device powered during the update).
- **Needs a fresh install:** no.
- **Tested on:** Radxa Cubie A7S. Test builds with the same profile, password and hotkey code ran on a real device: the first-boot password question, setting a password, SSH with it (and `linux` refused afterwards), the password surviving a reboot, the start-up profile setting (last used and always main), renaming profiles (including names with spaces, an apostrophe and double quotes), the double tap of the hotkey in all three modes, the switch message showing the profile's display name, and saves and savestates of two profiles staying apart (and coming back after switching back) on SNES, NES (2048), PlayStation (Crash Bandicoot, PCSX-ReARMed), Game Boy (Pokemon Red), N64 (Zelda Ocarina of Time, standalone emulator), Dreamcast (Sonic Adventure) and arcade (Gauntlet, libretro MAME).
  Not run on a device: DuckStation (PlayStation) and the Game Boy link cable saves following the profile, a new profile starting without a RetroAchievements login, the reminder that comes a week after choosing **Later** on the password question, every system not listed above, and going back to an older version.

## What changed

**Choose which profile the unit starts in.** New setting under Profiles: **Start in profile**, either the last one used (the default) or always the main profile.

**Open the profile screen with the hotkey.** Two quick taps of the hotkey button open the profile screen from the system list and the game list. One tap does nothing, and a tap that is part of a button combination is ignored, so existing combinations are not affected. The help bar shows `PROFILES (2x)`. In the profile screen, under **Shortcut**, you can set it to Auto (on once a profile exists), Always (the default on OctaneOS) or Never.

**The switch message shows the profile's name.** After switching, the message shows the name you gave the profile, not its folder name.

**A device password, if you want one.** The first time the unit starts, it asks whether to set a device password. It protects SSH and the network file share. Until you set one, both keep Batocera's default password (`linux`). You can choose **Set password**, **Later** (it asks again in a week) or **Don't ask again**. You can set or change it any time in Main menu > System settings > Security > Set device password. The SSH login now uses a SHA-512 hash instead of MD5. The password stays in Batocera's own settings, so the file share keeps working. On this board the stored password now survives a reboot (Batocera's own key changed at every start because the board has a random Ethernet address and no CPU serial number).

**Safer profile names.** A profile name typed in the screen can no longer be run as a shell command, and names with quotes and apostrophes work.

**More saves are meant to follow the profile.** DuckStation (PlayStation) memory cards and savestates, and Game Boy link cable saves, now go into the active profile's folder. This change was made but not run on a device yet (see above).

**New profiles start without a RetroAchievements login.** A new profile no longer inherits the login of the profile that created it, and it is named what you typed. Profiles you already made are not changed. This was not run on a device for this release.

**Settings changed on existing cards** (written once at the first boot after the update; a value the player already set is never touched):
- `profiles.boot=last` is added (the start-up profile setting).
- The device password question adds `octane.password.*` lines to `batocera.conf` the first time it is answered.

## Known issues

- **GameCube and Wii games do not start.** The default emulator for both is a standalone Dolphin that is not part of this image, so a game fails at launch.
- **N64 with the libretro core is slow**; the standalone emulator (the default) is fine. Do not switch a game to the libretro N64 core.
- **Dreamcast can stutter in heavy scenes.** The GPU runs at a fixed clock; a fix is being worked on, not part of this release.
- Some emulators keep saves outside the profile folders. Checked this release and found inside the profile: SNES, NES, PlayStation (PCSX-ReARMed), Game Boy, N64, Dreamcast and arcade (libretro MAME). The Dreamcast console settings file (`dc_nvmem.bin`, language and region) is shared by all profiles. Other systems have not been checked yet and may share saves.
- The device password question appears before Wi-Fi is set up on a brand new card.
- After you set a password, one old line (`octane.password.declined`) can stay in `batocera.conf`. It is harmless.
- The profile name at the top of the screen was missing once in our tests and came back by itself. We could not reproduce it. If you see it, please tell us what you were doing.
- **USB-C to DisplayPort with a plain (non power-delivery) cable** is tested only with a cable that does negotiate power delivery. If your screen stays black or says "no signal", please open the issue form "No picture, or the wrong picture, on a display".
- After the monitor is switched off and on, or goes to sleep, the picture may need a moment or a replug to come back.
- Some units can switch off completely under heavy load with no heatsink (heat is the main suspect). A heatsink and a fan avoid it in our tests.
- Standalone emulators (PPSSPP, Flycast, DuckStation, standalone mupen64plus) have their own vsync settings and were not tested.

## Files

- `boot.tar.xz` (+ `.md5`, `.sha256`): the over-the-air update. Devices fetch this.
- `boot.tar.xz.manifest` and `boot.tar.xz.manifest.sig`: the signed description of that update (board, version, size, SHA-256). Devices with signature checking refuse an update that does not match.
- `OctaneOS-<build>.img.gz`: a full image for a fresh install.
- `SHA256SUMS`: check downloads with `sha256sum -c SHA256SUMS`.
